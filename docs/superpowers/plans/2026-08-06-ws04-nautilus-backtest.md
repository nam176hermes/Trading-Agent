# WS-04C Isolated Nautilus Backtest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run a deterministic NautilusTrader 1.227.0 backtest only in an isolated CPython 3.12 closure, with the Python 3.11 control plane exchanging hash-bound command/result envelopes.

**Architecture:** The root graph never imports Nautilus. An external, policy-verified wheel and launcher are attested as a complete read-only closure supplied to the existing `EngineSpawnProvider`; it seals request bytes and executes the closure in Bubblewrap without network. The isolated launcher verifies the `RunBacktest` envelope, reads only hash-bound fixture/catalog inputs, converts the 04B `EngineTargetPortfolio` configuration, and emits one typed result envelope; 04D owns research-quality validation.

**Tech Stack:** CPython 3.11 root, isolated CPython 3.12, NautilusTrader 1.227.0, Bubblewrap, existing engine contracts/spawn provider, pytest.

## Global Constraints

- Root `pyproject.toml` remains `>=3.11,<3.12`; no Nautilus package or lockfile entry is added to it.
- Recreate caches only below `/home/thenam176/.cache/trading-agent/nautilus`; never use a global Rust toolchain.
- Engine input, wheel cache, Rust 1.95.0, LLVM, artifact manifest, closure manifest, command, and result are SHA-256 bound and fail closed on drift.
- No database, provider, broker, paper runtime activation, or live route is started.
- 04C handles fixture/catalog backtests only; public-data adapters and research promotion gates remain later packets.
